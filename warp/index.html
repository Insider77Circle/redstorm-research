Section I

What Is NEON-FORGE

NEON-FORGE is a parallel AI reverse-engineering system. It orchestrates three upstream tools — REA for activation extraction, Heretic for directional ablation, and OBLITERATUS for refusal-geometry mapping and surgery — into a single pipeline with a hard rule: nothing ships without a capability check.

Most refusal work stops at "it stopped refusing." NEON-FORGE treats that as the halfway point. Every run freezes a pre-surgery baseline, maps the refusal geometry, performs the ablation or surgery, re-probes, and then gates the result on measured capability preservation. If capability collapses, the run fails loudly instead of quietly producing a damaged model.

Why This Matters for AI Safety Research
Refusal is a mechanism, not a mood. If you can measure the direction a model uses to refuse, watch it re-form in deeper layers, and verify what else changed when you removed it, you can build better, more precise safety behavior — and audit claims about it with evidence instead of vibes. NEON-FORGE is instrumentation for that work.
Honest About Simulation
NEON-FORGE ships with a deterministic simulation backend so the full pipeline runs anywhere with no model download. Simulation numbers are internally consistent but say nothing about any real model — they validate the machinery, not the science. Real backends shell out to the upstream CLIs and record their output verbatim. If a required CLI is missing, the run errors. It never silently falls back to simulation and pretends otherwise.
Section II

Core Capabilities

Four integrated components covering the full loop — from probe design through ablation, geometry surgery, and gated verification.

// 01 — REA_ENGINE
Probe Design & Activation Extraction

Deterministic synthetic probe sets across neutral, borderline, and refusal-trigger categories, each with a harm-score band. The extractor drives the probe set against the target, records activations, and validates reconstruction fidelity — dimension consistency, category coverage, and refusal/neutral centroid separation — before anything downstream trusts the data.

Probe SetsActivation CaptureReconstruction Check
// 02 — HERETIC_ADAPTER
Precision Directional Ablation

Estimates the refusal direction by difference-of-means between refusal-trigger and neutral activations, then suppresses it by projection — and refits against the mutated target, iterating until the target refusal rate is met, separation collapses, or the pass budget is exhausted. Every pass is recorded, so the ablation is auditable step by step.

Difference-of-MeansIterative RefitPer-Pass History
// 03 — OBLITERATUS_ADAPTER
Refusal Geometry Mapping & Surgery

Maps the refusal subspace with centered-covariance PCA, keeps only axes aligned with the frozen pre-surgery refusal direction, and performs rank-k projection removal through the surgeon. Generates reversible steering vectors per geometry axis, so changes can be tested at runtime before any permanent weight modification is written to disk.

PCA SubspaceRank-k SurgeryReversible Steering
// 04 — MONITOR
Telemetry & Capability Gating

Every session event lands in an append-only log. The monitor freezes the pre-surgery baseline, re-probes after surgery, and fires explicit alert rules on recorded data only: capability preservation floor 0.85, activation drift ceiling 0.35, refusal reduction minimum 0.30, surgery rank cap 4, plus reversibility and convergence checks. Each run produces report.json, report.md, and a dashboard.

Append-Only TelemetryAlert GatesRun Reports
// 05 — DUAL BACKENDS
Simulation for Development, Real for Evidence

The simulation backend gives you a fast, deterministic loop for developing and testing the pipeline. Flip to the real backend and the same pipeline drives the upstream REA, Heretic, and OBLITERATUS CLIs against an actual model, recording output verbatim. Same stages, same gates, different evidentiary weight — and the system refuses to blur the two.

Sim BackendReal CLI BackendNo Silent Fallback
// 06 — REVERSIBILITY FIRST
Test Before You Commit

Steering vectors apply and remove cleanly, and verify() re-probes after both steps to measure — not assert — reversibility against a reference recording. The pipeline is designed so the reversible experiment always precedes the permanent edit, and the gate results travel with the artifacts.

Section III · Animation

The Pipeline, Stage By Stage

Every NEON-FORGE run walks the same six stages. Watch them light up in order — the loop below runs the sequence continuously, the way a real session steps through it.

// 01
Summon

Attach the target and freeze the pre-surgery refusal direction

// 02
Probe

Drive the probe set, record activations across categories

// 03
Distill

Map the refusal geometry and distill the subspace

// 04
Excise

Ablate or surgically remove the refusal directions

// 05
Verify

Re-probe, measure refusal reduction and drift

// 06
Rebirth

Gate on capability, snapshot artifacts, report

If any gate fails, the stage is documented as a result — not hidden, not retried silently.

Section IV

What A Run Looks Like

Outputs are evidence, not vibes: per-pass ablation history, geometry snapshots, alert values that tripped each gate, and a dashboard per run.

// Ablation Passes
❯ pass 1 — refusal rate 0.92 → 0.61 ❯ pass 2 — refusal rate 0.61 → 0.38 ❯ pass 3 — separation collapsed ✓ STOP — target met, history recorded
// Geometry & Surgery
❯ PCA axes aligned ≥ 0.35 kept ❯ rank-k projection removed, rank ≤ 4 ❯ steering vectors generated per axis ✓ reversibility measured, not assumed
// Capability Gates
❯ capability floor 0.85 — PASS ❯ activation drift ≤ 0.35 — PASS ❯ refusal reduction ≥ 0.30 — PASS ✓ artifacts → report.json / .md / dashboard
